# {{TOPIC}} answer rubric

Do not accept an answer unless it contains the topic-specific equivalents of:

- normalized problem statement;
- required input fields;
- mode and triage route;
- assumptions and caveats;
- derivation, proof, theorem match, or validation route;
- validation checks;
- final result or status label;
- unresolved gaps, if any.

## Strong answer

- Does not start from blind lookup.
- Matches the result to the exact problem specification.
- Separates facts, assumptions, derivation, and caveats.
- Gives enough detail for a later agent to resume from `notes.md` and
  `solution.md`.

## Weak answer

- Gives only a formula or result name.
- Hides assumptions.
- Uses the registry as proof.
- Skips danger zones.
- Does not state unresolved gaps.

## Reject answer

Reject or revise an answer that:

- applies a familiar result to a mismatched problem;
- claims final status without validation;
- omits the target or validity criterion;
- cannot be audited without the chat transcript.
